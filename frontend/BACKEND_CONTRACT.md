# Контракт API для фронтенда

Все обычные маршруты требуют cookie Identity, кроме регистрации и входа. Исключение для отдельного локального окружения Demo описано ниже. Ошибки сервиса: `{ error: string }`; ошибки привязки DTO — стандартный ответ ASP.NET. Сервер проверяет роль, исполнителя и допустимый этап заявки. UI не назначает себе права.

## Локальная демонстрация

Только в явно включённом окружении Demo доступны `GET /api/demo/accounts`
и `POST /api/demo/login/{key}` с заголовком `X-Rabotyagi-Demo: 1`. Каталог
возвращает `key`, `id`, `label`, `role`. Вход меняет реальную cookie-сессию на
одного из шести отмеченных учебных пользователей. Произвольный ID не принимается.
Изменённая роль или блокировка возвращает 409; неразрешённое окружение/запрос — 404.
Подробные ограничения и отдельная БД: [деморежим](../docs/demo-mode.md).

## Очереди суперадминистратора

`GET /api/order/queues` доступен Admin, Dispatcher, SuperAdmin и возвращает
`[{ status, count }]` по всем видимым заявкам, без ограничения первой страницей.
Отсутствующий статус означает нулевое количество. UI показывает четыре очереди
суперадминистратору. `GET /api/order?status=created&page=1&pageSize=100`
применяет необязательный фильтр статуса на сервере до пагинации; правила
видимости заявок сохраняются. Недопустимое значение статуса возвращает 400.

## Аккаунт и адрес

| Метод | Маршрут | Данные |
| --- | --- | --- |
| POST | `/api/account/register` | имя, фамилия, email, телефон, пароль, isPersistent; создаётся клиент |
| POST | `/api/account/login` | email, password, isPersistent |
| POST | `/api/account/logout` | без тела |
| GET | `/api/account` | профиль, nullable address, roles, roleName, availableUntil |
| PATCH | `/api/account/password` | oldPassword, newPassword |
| GET / POST | `/api/address` | адрес текущего аккаунта / сохранение JSON адреса |

Роли Identity: `User`, `Worker`, `Dispatcher`, `Admin`, `SuperAdmin`. Основная роль сохраняется и в `RoleId`; полномочия проверяются по Identity. Смена роли или блокировка обновляет security stamp и отзывает прежнюю сессию.

## Заявки

### Стоимость

Назначенный Worker предлагает цену, инициатор заявки принимает или отклоняет.
`POST /api/order/{id}/price` принимает `amount`, `scope`, `expectedUpdated`;
`POST /api/order/{id}/price/decision` — `accepted`, `reason`, `expectedUpdated`.
Обе операции доступны только до начала работы в `workerOnTheWay`.
Переход в `inProgress` возвращает 409 без принятой цены текущего исполнителя.
После переназначения требуется новое согласование. Принятую цену менять нельзя.
Поля, события, миграция и правила старых данных: [согласование стоимости](../docs/price-agreement.md).

### История действий

`GET /api/order/{id}/history` возвращает массив событий от старых к новым
(`occurredAt`, затем `id`), без пагинации в MVP. Требуются cookie и право просмотра
заявки по тем же правилам, что у GET заявки. Недоступная/отсутствующая заявка — 404,
анонимный запрос — 401. Существующая заявка без событий возвращает `[]`.

Поля: `id`, `occurredAt` (UTC), `eventType`, `actorUserId`, `actorNameSnapshot`,
`previousStatus` (nullable), `newStatus`, `executorId`, `executorNameSnapshot`,
`comment` (последние три nullable). Типы событий: `created`, `statusChanged`,
`executorAssigned`, `reportSubmitted`, `reportApproved`, `reportReturned`.
Операция создаёт одно событие, в том числе когда назначение или проверка меняет статус.
Комментарий хранит снимок текста отчёта/проверки; фотографии не архивируются.
Исторические имена не зависят от переименования, блокировки или удаления аккаунта.

История записывается атомарно с заявкой. Повтор операции после смены статуса
обычно вернёт 409 без события; идемпотентности HTTP нет, повтор создания может
создать новую заявку. Клиент не выполняет автоматические повторы записей.

Миграция: `20261017013451_OrderHistory`. Создаёт только таблицу и индекс, без
заполнения истории старых заявок. FK с Restrict запрещает удаление заявки с историей,
в том числе через существующие каскады от пользователя/адреса.
`AppDbContextFactory` позволяет генерировать миграции без запуска приложения;
для применения через EF CLI требуется явный `--connection` к выбранной БД.
Приложение по-прежнему применяет миграции при старте: запуск на рабочей БД
должен быть согласован отдельно. Откат Down удаляет таблицу вместе с историей.

| Метод | Маршрут | Поведение |
| --- | --- | --- |
| GET | `/api/order?page=1&pageSize=100` | очередь по роли, максимум 100 за страницу; необязательный userId фильтрует инициатора |
| GET | `/api/order/{id}` | доступная текущему аккаунту заявка |
| POST | `/api/order` | title, orderType, comment, addressText, scheduledAt; инициатор берётся из cookie; возвращает DTO с ID и 201 |
| PUT | `/api/order` | orderId, orderType, comment; описание до публикации меняет инициатор или администратор |
| PATCH | `/api/order/status` | orderId, status; публикация, отклонение, начало и закрытие |
| PATCH | `/api/order/executor` | orderId, executorId; работяга берёт себе, диспетчер назначает; требуется активный слот |
| POST | `/api/order/{id}/report` | multipart: Summary, WorkDone, ClientInformed, WorkplaceClean, Photos, KeepPhotoIds |
| POST | `/api/order/{id}/review` | approved, expectedUpdated, feedback; решение только инициатора, возврат требует комментарий |
| GET | `/api/order/{id}/photos/{photoId}` | авторизованная выдача файла |
| GET / POST | `/api/order/{id}/messages` | последние 100 сообщений / `{ text }`; закрытые заявки доступны только для чтения |

DTO заявки содержит ID, участников и телефоны, тип, статус, описание, заголовок, адрес, время, дату создания/обновления, отчёт, фото и комментарий проверки. У новых заявок `addressText` — снимок адреса, `scheduledAt` — UTC. Старые заявки без снимка используют существующий адрес из БД.

Клиент видит свои заявки. Работяга видит свои назначенные и опубликованные. Администратор и диспетчер видят общую очередь. Одновременное взятие защищено условным UPDATE; второй запрос получает 409. Другие изменения заявки используют optimistic concurrency по Updated.

| Из | В | Кто |
| --- | --- | --- |
| created | published / cancelled | Admin / SuperAdmin |
| created / published / workerOnTheWay | cancelled | Владелец заявки; после начала работ отмена запрещена (409), чужая заявка — 403 |
| published | workerOnTheWay | Worker со слотом / назначение Dispatcher |
| workerOnTheWay | inProgress | назначенный Worker |
| inProgress / rework | workFinished | назначенный Worker отправляет полный отчёт |
| workFinished | completed / rework | Инициатор через POST review с expectedUpdated |
| approved (прежние заявки) | completed / rework | Инициатор через POST review с expectedUpdated |

## Специалисты и пользователи

### Переназначение исполнителя

`PATCH /api/order/{id}/executor` — отдельная операция замены для Dispatcher и
SuperAdmin. Первичное назначение через `/api/order/executor` не изменилось.
Тело: `executorId`, `expectedExecutorId`, `expectedUpdated` (строка `updated`
из DTO заявки без преобразования точности), `reason` (непустой, до 2000 символов).

Замена разрешена только из `workerOnTheWay`, `inProgress`, `rework` и только
на другого незаблокированного Worker с открытым слотом. Новый статус всегда
`workerOnTheWay`. Старый исполнитель больше не обладает правами назначенного
работника; другие основания доступа, например владение заявкой, сохраняются.
Закрытые, отменённые, ожидающие проверки/закрытия и неназначенные заявки менять
нельзя. Причина и оба исполнителя записываются в одном событии `executorChanged`:
новый исполнитель — `executorId`/`executorNameSnapshot`, прежний — nullable
`previousExecutorId`/`previousExecutorNameSnapshot`.

Изменение и событие сохраняются в одной транзакции. Устаревшая версия заявки,
недоступный исполнитель и повтор запроса возвращают 409 без нового события.
Данные отчёта и фото при замене не удаляются. Старый отчёт нельзя принять, пока
новый исполнитель не начнёт работу и заново не отправит отчёт. При повторной
отправке можно использовать сохранённые фото; архива версий фотографий нет.
После возврата в `workerOnTheWay` действует существующее правило отмены владельцем.

Миграция `20261023213615_ExecutorReassignment` добавляет две nullable-колонки
прежнего исполнителя в историю, не заполняет и не меняет старые события.

| Метод | Маршрут | Поведение |
| --- | --- | --- |
| GET | `/api/worker` | специалист видит себя; сотрудники — команду с доступностью и числом активных заявок |
| PUT | `/api/worker/availability` | `{ hours: 0..12 }`; 0 закрывает слот, остальные значения открывают/продлевают от текущего времени |
| GET | `/api/user?page=1&search=` | SuperAdmin, 50 пользователей за страницу |
| PUT | `/api/user/{id}/role` | SuperAdmin, `{ role }`, одна основная роль; собственную менять нельзя |
| PUT | `/api/user/{id}/blocked` | SuperAdmin, `{ blocked }`; собственный аккаунт блокировать нельзя |

Без дополнительных уровней архитектуры: контроллер → конкретный сервис → AppDbContext / UserManager. Worker и Users расположены в собственных папках Features с DTO. Фото лежат вне wwwroot в volume; отдельное публичное хранилище не используется.

Постраничный список теперь использует `GET /api/order/page` с серверным поиском,
фильтрами и общими счётчиками; размер страницы в UI — 20. Подробнее:
[обновление списка и ошибки](../docs/order-list.md).

Все API имеют лимиты частоты; 429 возвращает JSON error/retryAfterSeconds и
Retry-After. Неверные данные входа (включая неизвестный/заблокированный аккаунт)
дают одинаковый 400. Новые пароли — 10–128 символов со стандартной сложностью
Identity. Cookie в Production требуют HTTPS; CORS только для точных origins.
Подробности: [защита входа](../docs/login-security.md).
