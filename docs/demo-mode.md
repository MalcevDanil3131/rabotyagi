# Локальная демонстрация Работяг

## Запуск одной кнопкой на этом компьютере

Дважды щёлкните **Start-Demo.cmd** в корне проекта. Откроется окно запуска,
а после проверки готовности — http://127.0.0.1:3001 в обычном браузере.
Логины и пароли учебных аккаунтов вводить не нужно.

Кнопка собирает актуальный код и поднимает отдельный Compose-проект
**rabotyagi-demo** с тремя контейнерами. В Docker Desktop откройте Containers,
раскройте **rabotyagi-demo** и нажмите порт **3001** у **frontend**.
Для запуска и после изменений кода используйте Start-Demo.cmd — он пересобирает образы
и пересоздаёт frontend/API. При ошибке окно останется открытым.

Первый запуск требует Docker Desktop и интернета для скачивания образов и зависимостей.
Сборка .NET и React выполняется внутри Docker. Новый стенд получает отдельную БД
`rabotyagi_demo_docker` и текущий набор учебных сценариев. Прежнее демо на 5173
с его заявками сохраняется отдельно и автоматически сюда не переносится.

Данные сохраняются между запусками. Настройки конкретного стенда, зашифрованный
пароль PostgreSQL и журнал сборки находятся в `.tools/docker-demo/`, исключённой из Git.
Данные БД находятся в volume `rabotyagi-demo_postgres_data`, фотографии, ключи
cookie и очередь очистки файлов — в `rabotyagi-demo_demo_files`.
Не удаляйте папку конфигурации или volumes демобазы. Пароль защищён Windows DPAPI и доступен
только тому же Windows-пользователю на этом компьютере; кнопка не является
переносимым установщиком для другого ПК. Системная политика PowerShell не меняется:
параметр ExecutionPolicy действует только в процессе запуска локального скрипта.

Основной Compose, приложение на порту 3000 и основная база не пересобираются
и не обновляются. Если Docker Desktop выключен, кнопка запускает его; при этом
Docker может автоматически поднять другие ранее созданные контейнеры согласно
их собственным restart policy. Скрипт не меняет эти настройки и не запускает
основной Compose. Новые миграции текущего кода применяются только к демобазе.

Основные файлы кнопки — `Start-Demo.cmd`, `scripts/Start-DockerDemo.ps1`
и `compose.demo.yaml`. Файл `.env` основного приложения при запуске не читается.
Для диагностики без открытия браузера у PowerShell-скрипта есть `-NoBrowser`.

### Сеть и готовность Docker-стенда

На компьютере опубликован только `127.0.0.1:3001`. PostgreSQL и API не публикуют
порты. Nginx и Kestrel используют общее сетевое пространство контейнера frontend,
поэтому Nginx обращается к API на loopback `127.0.0.1:5189`.
Проверки локального адреса, Host, Origin и заголовка демовхода продолжают действовать.
Production-конфигурация авторизации для этого не меняется.

Healthcheck frontend проверяет и статическую страницу, и получение списка
демоаккаунтов через API. Кнопка ждёт готовности стенда, затем открывает браузер.
Порт 55439 старого PostgreSQL относится к прежнему локальному стенду.

Проверка Docker-стенда через PowerShell 7

```powershell
pwsh -NoProfile -File .\tests\DockerDemoChecks.ps1 -Rebuild
```

Проверяются изоляция портов и volumes, вход всех ролей, действительные заявки,
цены, история и фото через Nginx, отказы чужим Origin/Host, реакция healthcheck
на остановку API, повторная сборка/пересоздание, сохранность заявок и сессии.
Проверка использует только проект rabotyagi-demo и не удаляет volumes.
На 12 ноября успешно выполнены 55 проверок Docker-стенда, 32 теста фронтенда
и 19 проверок ограничений деморежима без доступа к БД. Полный ручной проход
браузерного интерфейса и кнопок Docker Desktop в эту проверку не входил.

## Что такое деморежим

Деморежим позволяет входить одним нажатием как клиент, два разных исполнителя,
диспетчер, администратор или суперадминистратор. Сервер создаёт настоящую сессию
Identity выбранного учебного пользователя. У этих аккаунтов нет паролей;
интерфейс не подменяет роли локально. Есть кнопка возврата к суперадмину.

## Запуск исходников для разработки

Прежний локальный стенд на этом ПК запускается через
`powershell -File .\scripts\Start-Demo.ps1`. Он использует `.tools/demo-runtime/`
и отдельный PostgreSQL на 55439. Ниже описан ручной запуск исходников.

Нужны .NET 10, Node.js 24+, pnpm и отдельный локальный PostgreSQL.
Владелец стенда заранее создаёт **новую пустую** базу, например
`rabotyagi_demo_local`, и выдаёт отдельному пользователю права только на неё.
Не копируйте в неё рабочие данные. Существующие базы для этого не подходят.

В терминале PowerShell из корня проекта задайте строку подключения через
переменную окружения. Пример ниже содержит только placeholders; реальные
секреты вводите через защищённую конфигурацию, не сохраняйте их в Git или
истории команд:

```powershell
$env:ConnectionStrings__DemoConnection = 'Host=127.0.0.1;Port=<DEMO_PG_PORT>;Database=rabotyagi_demo_local;Username=<DEMO_DB_USER>;Password=<DEMO_DB_PASSWORD>'
dotnet run --project rabotyagi --launch-profile Demo
```

Профиль задаёт `ASPNETCORE_ENVIRONMENT=Demo`, `Demo__Enabled=true`,
`BootstrapAdmin__Enabled=false`. Если в окружении уже задан DOTNET_ENVIRONMENT,
его также нужно установить в Demo. API слушает только `127.0.0.1:5189`.
Существующий механизм приложения автоматически применит миграции **к выбранной
демобазе**. В том числе нужна имеющаяся миграция `20261023213615_ExecutorReassignment`.
Новых миграций специально для деморежима и очередей нет.

Во втором терминале:

```powershell
cd frontend
pnpm.cmd install
pnpm.cmd dev:demo
```

Откройте http://127.0.0.1:5173 и выберите аккаунт в блоке «Быстрый вход для показа».
Если порт занят, сначала освободите его или передайте Vite другой `--port`. Для этого запуска уберите старое
переопределение `API_PROXY_TARGET` из окружения/`.env.local`, если оно указывает
на обычный API: режим demo по умолчанию проксирует API на `127.0.0.1:5189`.

## Что подготовлено

- Шесть учебных аккаунтов и 12 актуальных сценариев с префиксом «ДЕМО ·» в названии.
  Новый цикл использует восемь этапов, включая завершение и отмену клиентом. Назначенные заявки
  распределены между обоими исполнителями.
- Для цены есть отдельные примеры: предложение ещё не отправлено, 3 200 ₽ ожидают
  решения клиента, 2 800 ₽ отклонены, 2 500 ₽ согласованы и можно начинать работу.
  У заявок в работе, с отчётом, на доработке и завершённых стоимость уже согласована;
  учебная история содержит предложение исполнителя и согласие клиента до начала работ.
- Сумма и результат согласования видны прямо в списке заявок. Для проверки войдите
  клиентом и откройте «ДЕМО · Цена ждёт решения клиента», затем переключитесь на
  исполнителя № 2 для этой же заявки. До согласия клиента начать работу нельзя.
  Исполнитель № 1 может изменить отклонённое предложение. Все действия идут через
  обычный API и сохраняются. Указанные суммы описывают начальное состояние примеров.
- Учебные отчёты используют явно обозначенный образец PNG. Для полноценного
  показа фотографии можно заменить через обычную отправку отчёта.
- Слоты исполнителей открыты на 12 часов от первого создания. После истечения
  срока войдите исполнителем и откройте слот обычной кнопкой.
- У суперадмина четыре быстрые очереди с общими счётчиками и переход к управлению
  пользователями. Эти очереди доступны ему и в обычном режиме приложения.

После входа панель «ДЕМО» остаётся наверху. При переключении старая карточка и
списки сбрасываются. Несохранённые формы теряются. Cookie общая для вкладок
одного профиля браузера: для одновременного показа двух ролей используйте разные
профили. Перезагрузите другие открытые вкладки после переключения аккаунта.
Старое демо на 5173 и новое на 3001 также используют одно имя demo-cookie на
127.0.0.1. При переключении между этими стендами может потребоваться повторный
быстрый вход. Для одновременного показа используйте отдельные профили браузера.

## Повторный запуск и ограничения

Заявки, история и пользователи сохраняются в PostgreSQL. Повторный запуск
не восстанавливает роли, пароли, блокировки, слоты или исходные заявки. Если
роль учебного аккаунта изменили или его заблокировали, быстрый вход вернёт ошибку;
исправление возможно штатным управлением пользователями под суперадмином.
Для нового чистого показа создайте другую новую демобазу с допустимым префиксом.
Автоматического удаления или сброса баз нет.

Наборы учебных сценариев версионируются. При первом запуске обновлённого сервера
на ранее созданной демобазе текущий набор `client-acceptance-v2` добавляет 12 новых примеров. Прежний набор `price-agreement-v1` сохраняется, если он уже был создан.
Старые заявки, история, роли и решения пользователей сохраняются без изменения;
задним числом цена и события им не добавляются. Поэтому старые примеры могут
по-прежнему показывать «Стоимость не зафиксирована» — новые легко найти по «ДЕМО».
Повторный запуск не создаёт дубликаты. Маркер версии хранится в существующей таблице
Identity claims, в одной транзакции с примерами; отдельная миграция для этого не нужна.
Обновления демонстрационных наборов добавляются явно при разработке новых функций,
сами по себе изменения схемы БД учебные данные не обновляют.

При запуске исходников фото и ключи cookie находятся в `rabotyagi/.demo/<имя базы>/`; каталог исключён
из Git. Имя cookie отличается от обычного приложения. Не удаляйте ключи,
если хотите сохранить сессии между перезапусками.

Деморежим по умолчанию выключен, запрещён в Development и Production, требует
отдельного DemoConnection с именем `rabotyagi_demo_*`, не совпадающим с обычными
подключениями. Пользовательские endpoints Kestrel и bootstrap одновременно с ним
запрещены. Быстрый вход принимает только фиксированные ключи и проверяет маркер
учебного аккаунта, роль, блокировку, локальный адрес/Host/Origin и специальный
заголовок. В обычном режиме эти endpoints возвращают 404.

Этот режим предназначен для локального показа. Docker-стенд использует внутренний
Nginx и loopback-публикацию. Пароль для входа в учебные аккаунты намеренно не нужен.
Не запускайте обновлённое приложение на существующей рабочей БД без отдельного
согласования: обычный запуск по-прежнему автоматически применяет миграции.

## Проверки

Без PostgreSQL можно выполнить `dotnet run --project tests/WorkflowChecks -- --demo-guards-only`
и `pnpm.cmd test` в frontend. Полный WorkflowChecks требует явного подключения

## Приёмка без диспетчера

Текущий набор `client-acceptance-v2` содержит «ДЕМО · Клиенту: принять работу»
и «ДЕМО · Клиенту: вернуть работу на доработку». Войдите клиентом и откройте
карточку: есть фотоотчёт, согласованная сумма, «Принять работу» и «На доработку».
Принятие сразу завершает заявку. Для возврата обязательно замечание.
Переключитесь на исполнителя №2, откройте возвращённую заявку и отправьте отчёт
ещё раз, затем примите его клиентом. Старые отчёты в Approved также завершает клиент.
Готовые примеры «Исправить замечания клиента» (исполнитель №1) и «Работа принята
клиентом» показывают сохранённое решение и историю. Сотрудники видят ход приёмки,
но не принимают решение за владельца. Новых миграций для этой функции нет.
## Проверка списка и страниц

Список показывает по 20 заявок с кнопками «Назад»/«Далее» и общим количеством.
Текущих сохранённых демозаявок достаточно для нескольких страниц. Обновление
сохраняет страницу; поиск ищет по всей доступной выдаче. Новые учебные записи
специально для пагинации не добавляются. Сценарии ошибок и проверки описаны в
[документации списка](order-list.md).

## Защита входа и запросов

Демо использует те же ограничения частоты API и входа. Быстрое переключение
доступно до 30 запросов за минутное окно с одного IP; далее показывается ожидание.
Обычный вход ограничен 10 попытками за минутное окно, новые регистрации — 5 за
10 минут. Подробности настроек, тестов и ограничений: [защита входа](login-security.md).
Пароли демоаккаунтам не устанавливаются. Блокировку после неверных паролей проверяем
на отдельных временных аккаунтах, чтобы сохранить готовый стенд.

## Проверка резервного копирования

`Test-Backups.cmd` использует прежний PostgreSQL на 55439 и `.tools/demo-runtime/`.
Новый Docker-стенд на 3001 этим механизмом пока не копируется.
Проверка создаёт новые временные БД на отдельном PostgreSQL, проверяет
шифрованную копию вместе с фотографиями и восстановление, затем удаляет только
свои тестовые БД. Текущая демобаза не копируется и не изменяется этим тестом.
Ручное копирование демобазы: PowerShell 7, `scripts/Backup-Demo.ps1`.
[Инструкция, парольная фраза и восстановление](backup-restore.md).
Расписание основной БД и задания Windows при проверке не включаются.
