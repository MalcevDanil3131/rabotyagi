# Список заявок: обновление, страницы и ошибки

Интерфейс использует `GET /api/order/page`: `page` (от 1), `pageSize` (1–100,
в интерфейсе 20), `status`, `scope` (all/mine/active/review), `search` (до 200
символов), `quality`. Прежний GET /api/order сохранён для совместимости.
Все запросы проходят существующий VisibleOrders: сотрудник видит общую очередь,
клиент — свои заявки, работник — назначенные ему, свои и опубликованные.

Ответ содержит items, page, pageSize, totalCount, stats и statusCounts.
Фильтры и поиск применяются в PostgreSQL до разбиения на страницы. Поиск без
учёта регистра охватывает название, адрес, номер (включая первые восемь символов)
и имя инициатора; %, _ и обратный слеш трактуются буквально. Mine означает
инициатора или назначенного исполнителя, active — путь/работа/доработка,
review — ожидающие клиента отчёты, принадлежащие ему, либо видимые сотруднику.
Quality дополнительно ограничивает выдачу приёмкой. Статус из быстрой очереди
можно сочетать с вкладками; выбор другого статуса или метрики снимает очередь.

TotalCount относится к текущему запросу. Stats и statusCounts отражают все
доступные пользователю заявки, поэтому метрики больше не зависят от первой
страницы или поиска. Ответ формируется в транзакции RepeatableRead: строки
и счётчики относятся к одному снимку. Сортировка Created DESC, Id ASC разрешает
совпадения времени. Если последняя страница опустела, сервер возвращает новую
последнюю; для пустой выдачи page=1. Невалидные параметры получают 400.
Это обычная пагинация по смещению: изменения между разными запросами могут
сдвигать границы страниц. Курсоров и общего снимка на всю сессию просмотра нет.

Обновление сохраняет номер страницы и фильтры. Поиск запускается с задержкой
300 мс; смена поиска/фильтра возвращает на первую страницу. Последовательность
запросов предотвращает публикацию устаревшего результата или ошибки при смене
страницы/фильтра, аккаунта или размонтировании. Фоновый опрос раз в 15 секунд
работает на любой странице, при возвращении фокуса — дополнительное обновление.
Он приостанавливается для скрытой вкладки, сохранения, диалогов и формы отчёта.
Запросы мутаций автоматически не повторяются.

Ошибка начальной загрузки не показывается как пустой список. Есть отдельная
кнопка повторной загрузки. При сбое обновления прежняя страница остаётся с
предупреждением об устаревших данных. Ошибка специалистов не блокирует заявки.
Запросы ограничены 20 секундами; ошибка чтения ответа, HTML прокси и ошибки
валидации обрабатываются в api.ts. Статус 401 вызывает выход к форме входа,
404/403 — сообщение о недоступности, 409 — обновление с сохранением ошибки
действия. Успешное сохранение не считается неудачным из-за последующего сбоя
загрузки: действие закрывает свою форму, а загрузка показывает отдельную ошибку.

Карточка загружается через GET /api/order/{id} независимо от текущей страницы.
Она остаётся открытой после выпадения заявки из фильтра. Смена карточки игнорирует
поздние ответы. После создания открывается карточка новой заявки, даже если она
не входит в текущий фильтр или страницу. Начальная ошибка карточки имеет кнопку повтора.
При ошибке
обновления карточки действия блокируются до успешной загрузки, при 403/404 старые
детали скрываются. Форма фотоотчёта не заменяется фоновым ответом во время ввода.

Новых миграций и новых учебных записей нет. Существующие демозаявки дают несколько
страниц при размере 20. Проверка в демо: выбрать клиента/суперадмина, перейти
«Далее», нажать обновление и убедиться, что страница сохраняется; найти заявку
со второй страницы через поиск; открыть её, отменить или принять и проверить
обновление списка и карточки. Для сбоя сети остановить только демо-API, нажать
обновление, затем запустить Start-Demo.cmd и повторить загрузку. Основной Compose
для этих проверок не нужен.

Изменённые файлы:

- Сервер: `API/Features/Order/OrderService.cs`, `OrderApiController.cs`,
  новый `DTOs/OrderPageDto.cs` (пути относительно rabotyagi/).
- Интерфейс: `frontend/src/ConnectedDashboard.tsx`, `api.ts`, `components.tsx`,
  `styles.css`, новый `orderListLoader.ts`.
- Тесты: `tests/WorkflowChecks/DemoIntegrationChecks.cs`, новый
  `OrderPaginationChecks.cs`, новый `frontend/tests/orderList.test.ts`.
- Документация: этот файл, `docs/demo-mode.md`, `frontend/BACKEND_CONTRACT.md`,
  `tests/WorkflowChecks/README.md`.

Тесты PostgreSQL используют только временные базы rabotyagi_demo_checks_*,
проверяют более 100 записей, порядок, фильтры, поиск, доступ, пустую/последнюю
страницу и переход статуса. Fixtures удаляются только внутри этой временной БД.
Тесты загрузчика проверяют гонки запросов, повтор загрузки, сохранение страницы,
отмену публикации после размонтирования и сбои. Тест HTTP проверяет таймаут без
автоповтора действия. Визуальная ручная проверка в этом сеансе не завершена:
разрешение на управление Opera истекло по времени.
